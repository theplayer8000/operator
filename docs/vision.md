# Operator Vision

Operator is not a productivity application.

It is the operating system for my life.

Its purpose is to centralise planning, execution, learning, knowledge, infrastructure, projects and long-term goals into a single interconnected platform.

The application is expected to evolve over many years.

Every feature should contribute to a larger ecosystem rather than exist in isolation.

## Long-term Vision

Operator should eventually become my central interface for:

- Mission management
- Knowledge management
- Learning
- Journalling
- Homelab management
- Infrastructure
- AI assistants
- Documentation
- Decision logging
- Life planning

The application should understand relationships between these areas rather than treat them as separate pages.

## AI Philosophy

AI is not a feature.

AI is a collaborator.

Future AI systems should:

- understand my projects
- understand my goals
- understand historical decisions
- understand documentation
- understand relationships between entities

Operator should eventually become the persistent memory layer that allows AI assistants to reason about my work over many years.

## Accessibility

Operator is expected to be used from both desktop and mobile devices.

The interface should be responsive, touch-friendly and usable over Tailscale from anywhere.

Desktop remains the primary experience, but no core workflow should require a desktop computer.

## Design Principle

Today Operator is a local-first React application.

Tomorrow it may become a much larger platform.

Architectural decisions should avoid limiting that future unless there is a compelling reason.
